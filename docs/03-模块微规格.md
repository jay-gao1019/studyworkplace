> **v2.0 落地映射说明**：本文全部业务规则（M1–M9）跨技术栈有效，逐条实现于后端 `com.studdy.domain`（纯逻辑）与 `com.studdy.service`（事务编排）；文中出现的 `core/xxx.ts`、`stores/xxx`、IndexedDB 等 v1.x 路径按 docs/02 §3 映射表对应到 Java 类；"去重/事务"由数据库唯一约束 + `@Transactional` 保证（较 v1.x 前端防抖更强）。M9.3 的日键以服务器本地日期为唯一口径。

## M1 金币账本与激励引擎（core/coin, core/streak）

**职责**：所有金币变动的唯一入口；余额/累计/统计/等级/连续天数的推导。

### 流水（CoinTx）类型

| type | 触发 | 金额 | 必填引用 |
|---|---|---|---|
| `daily_checkin` | 每日签到 | +配置值（默认20） | dayKey |
| `task` | 学习/生活任务勾选 | ±配置值 | taskItemId, dayKey |
| `textbook` | 教材条目打卡 | +配置值 | treeNodeId |
| `redeem` | 商店兑换 | −价格 | shopItemId |
| `redeem_refund` | 家长撤销兑换 | +价格 | redemptionId |
| `reverse` | 取消勾选冲正 | 反向等值 | refTxId |
| `screen_over` | 屏幕超时罚扣 | −配置值 | sessionId, dayKey |
| `habit_milestone` | 习惯里程碑奖励 | +配置值 | habitId, milestone |
| `manual` | 家长手动奖惩 | 任意 | reason(必填≥2字) |

### 规则

- M1.1 MUST 余额=Σamount、累计=Σ正数amount，由流水实时推导；任何代码不得直接持久化余额字段。
- M1.2 MUST 同一 (profileId, sourceRef, dayKey) 至多产生一条非冲正流水（每日一次原则的账本级兜底）。
- M1.3 MUST 冲正流水只引用原流水，金额取反；原流水永不被修改或删除。
- M1.4 MUST 等级按累计金币落入区间 [t0,t1,t2,t3,t4]（默认 0/200/600/1500/3000 → 小嫩芽/绿幼苗/向阳花/知识树/小学霸），只升不降；跨过阈值当次触发升级事件。
- M1.5 MUST 连续打卡：当日存在 ≥1 条非 `redeem/redeem_refund/manual(负)` 流水即记为打卡日；`streak = 从今天(或昨天)向前连续打卡天数`；今天未打卡时 streak 显示"昨天为止"的值，今天过完仍未打卡则明天归零。
- M1.6 SHOULD 统计聚合（日/月/年柱状图）输出 `{label, income, expense}[]`，缺失日期补零，最多返回最近 400 个桶。
- M1.7 MUST 扣币项与 manual 负数项仅家长侧（PIN 后）可发起。

### 边界条件

| 场景 | 行为 |
|---|---|
| 余额不足兑换 | 兑换按钮禁用 + 差额提示（M3.2） |
| 冲正一笔已冲正的流水 | 拒绝（幂等），提示"已经取消过啦" |
| 本地时区跨日（23:59 勾选）| 以点击时刻的本地 dayKey 归属，不做 UTC |
| 流水为空 | 余额0、streak 0、等级 0 级 |
| 导入的流水校验和不符 | 拒绝导入并指出首个不一致档案 |

## M2 每日学习计划（core/rules, stores/plan）

**职责**：任务项定义（AdminConfig）× 每日勾选（DailyPlan）的学习侧执行与结算。

### 数据

- `TaskItem`（配置）：id、name、icon、amount(±)、category(`study`/`life`，M1 共用)、gradeScope(`all`/`[g…]`)、term(`all`/`上`/`下`)、enabled、sort。
- `PlanCheck`（执行）：profileId、taskItemId、dayKey、status(`done`/`undone`)、checkedAt、txId。

### 规则

- M2.1 MUST 今日清单 = enabled 且 gradeScope 命中当前档案年级的任务项；无配置命中时显示空态引导家长配置。
- M2.2 MUST 勾选→（去重校验→写 PlanCheck→生成 task 流水→返回新余额）四步原子化；任一失败整体回滚。
- M2.3 MUST 取消勾选→PlanCheck 置 undone→生成 reverse 流水（引用原 txId）。
- M2.4 MUST 扣币类任务（amount<0）默认不出现在孩子端"可自勾"列表；孩子端仅显示"今日已被扣：原因"记录，勾/发起在家长后台。"今日已被扣"清单=当日负数流水中仅罚则类（家长手动负项、屏幕超时、扣币任务勾选），不含取消勾选产生的冲正（reverse，成对中和）与商店兑换（主动消费，P5 已展示）（v2.1 澄清）。
- M2.5 MUST 签到按钮按 profileId+dayKey 去重；完成后按钮进入当日禁用态。
- M2.6 SHOULD 勾选成功后 800ms 飘字 `+5 🪙`，失败给可读 toast。
- M2.7 MUST 昨日遗留的未勾项不自动结转（今日清单永远=配置快照，防"欠账滚雪球"）；周报里可见历史完成率。

### 边界

重复点击（连点）按 300ms 防抖；配置项被禁用但历史有勾选→历史照显示（灰），今日清单不再出现；改任务金额只影响此后勾选产生的流水。

## M3 兑换商店（stores/shop）

**职责**：商品定价、兑换记账、家长确认兑现闭环。

### 规则

- M3.1 MUST 商品字段：id、name、icon、price、enabled、stock(`unlimited`/n)。
- M3.2 MUST 兑换前置校验：`balance ≥ price`（+库存充足）；不满足时按钮禁用并显示"还差 X 金币"。
- M3.3 MUST 兑换成功 = 生成 Redemption(`pending`) + `redeem` 流水，同一事务。
- M3.4 MUST 家长在后台可将 pending→`redeemed`（归档）或撤销→生成 `redeem_refund` 流水、Redemption 置 `cancelled`。孩子不可自行撤销。
- M3.5 MUST 商店不做任何自动兑现动作，UI 文案明确"兑换后请与爸爸妈妈确认"（对应需求 §3.3 设计取舍）。
- M3.6 SHOULD pending 记录在孩子端"我的兑换"列表可见（状态徽标：待兑现/已兑现/已撤销）。

### 边界

兑换瞬间余额被并发改变→事务内重校验；已 redeemed 的记录家长只能追加 manual 补偿流水，不可回滚；删除商品不影响历史 Redemption（快照冗余存 name/price）。

## M4 教材目录打卡（core/knowledge/progress）

**职责**：三科人教版目录树（可勾选）→ 科目进度百分比 → 打卡金币。

### 规则

- M4.1 MUST 树结构四级中，教材打卡挂在**叶子条目**（课文/课时级，如"古诗二首""Unit 1 Part A"）；分组节点（单元）只聚合不可勾。
- M4.2 MUST 条目勾选→`textbook` 流水（金额=textbookCoinValue 全局配置，默认 +5）；取消→冲正。
- M4.3 MUST 科目进度 = 已勾叶子数 / 当前(科目,年级,学期)叶子总数，向下取整到 1%；未登录年级该科显示 0%。
- M4.4 MUST 数学树含平行分支 `校内` 与 `奥数`（奥数叶子默认不计入校内进度，单独显示奥数进度）。
- M4.5 MUST 英语 Unit 下四分组（话题词汇/核心句型/语音/交际与文化）仅作展示分组，勾选粒度到条目。
- M4.6 SHOULD 页右上角三科进度徽标实时刷新；跨页面切换 <100ms。
- M4.7 MUST 电子书入口（v2.2，FR-24）：教材页每个**单元分组标题行**、位于"🎯自测"之前，提供 [📖 打开电子书] 按钮；书目按目录约定 `data/ebooks/<subject>-<年级><上|下>.pdf` 由家长放入，前端经 `/api/ebook/index` 判断就绪态——未就绪按钮置灰并提示"请爸爸妈妈先把电子书放进 data/ebooks 目录（如 math-4上.pdf）"。就绪则弹层内嵌浏览器 PDF 查看器（iframe `#page=<页码>`）；页码取种子分组可选字段 `ebookPage`（docs/10），缺省从第 1 页打开。电子书文件不进数据库、不参与备份 payload。

### 内容规格（v1.0 seed）

- 语文：1–6 年级上下册，单元→识字/汉语拼音(一上)/阅读 分组→课文条目（公开教材目录）。
- 数学：校内按"第n单元"→课时条目；奥数按专题（计算/计数/数论入门/趣味应用/几何/综合）分年级挂 2–4 个专题条目。
- 英语：按 Unit→四分组→条目。
- 验收口径：任一(科目×年级×学期)组合叶子数 ≥8，全量条目总数 ≥ 600。

## M5 知识体系树与自测（stores/knowledge, core/quiz, core/mastery）

**职责**：四级树浏览、知识点自测、判分、掌握度分级与筛选；"学练诊同一棵树"的实现体。

### 数据结构（详见 05 文档）

TreeNode{ id, spaceRef, parentId, kind:`grade|module|unit|leaf`, title, order }；Quiz{ id, leafId, type:`single|blank`, stem, options?, answer, explanation }；AttemptRound{ profileId, leafId, quizSetHash, startedAt, answers[], rate, mastery }。

### 判分规则

- M5.1 MUST 单选：选项 id 精确匹配。
- M5.2 MUST 填空：两侧 `trim` + 全角转半角 + 连续空白折叠 + **统一小写**（判分不区分大小写，v2.0 补充）后字符串全等（多答案题用 `answerAccepts[]` 任一匹配）。
- M5.3 MUST 即时反馈：提交→判分→无论对错展示正确答案+解析；答错不禁看解析。
- M5.4 MUST 一轮=该叶子当前全部题目各答一次；本轮全部提交后才计算 rate 并落 AttemptRound。

### 掌握度规则

- M5.5 MUST 分级映射：rate≥0.9 精通(绿)、0.8≤rate<0.9 掌握(蓝)、0.3≤rate<0.8 部分掌握(黄)、rate<0.3 未掌握(红)、无轮次 未答(灰)。0.8/0.9 边界归属高档（含下限）。
- M5.6 MUST 有效轮次 = quizSetHash 与当前题目集一致的最近一轮；hash 失配→节点标"待重测"（视觉=灰底+叹号角标），不参与统计。
- M5.7 MUST 顶部统计四项：末级知识点数、大纲节点总数、已答知识点数、精通+掌握占比（分母=有效轮次节点数）。
- M5.8 MUST 六档筛选（全部/精通/掌握/部分/未掌握/未答）过滤叶子并保留祖先路径可见；"未掌握"档即"明日攻关清单"，提供"开始攻关"按钮按序打开红点叶子。
- M5.9 SHOULD 重做入口始终可用；新轮次覆盖旧轮次为"有效"，旧轮次保留在档案历史（周报可查）。
- M5.10 MUST 自测答题不直接产生金币；完成一个知识点整轮首次达"精通"奖励 +textbookCoinValue（防"为刷题而刷"，只奖学会不奖做题）。

### 树渲染

懒展开（子节点挂载时才渲染）；>2000 节点的分支用虚拟列表；键盘上下键在可见节点间移动（NFR-06）。

## M6 生活管理（stores/life, core/life/screen）

**职责**：作息、家务、屏幕时间、习惯链四类生活数据与激励联动。

### M6-A 作息打卡

- M6.1 MUST 两项固定任务：`sleep`(按时上床) 与 `wake`(按时起床)，目标时间与宽限分钟（默认 21:30±15 / 7:00±15）家长可配。
- M6.2 MUST 判定时钟窗口：sleep 在 [target−60min, target+宽限] 内打卡=按时(+币)；窗口后=迟(0 币)；wake 同理。打卡即记录实际时刻。
- M6.3 SHOULD 周报显示按时率；连续 7 天按时 sleep 奖励 habit_milestone +10。

### M6-B 家务任务池

- M6.4 MUST 家务为 category=life 的 TaskItem，复用 M2 全部结算规则（每日一次、冲正等）。
- M6.5 SHOULD 默认池：倒垃圾+3、洗碗+5、整理书桌+4、叠被子+2、浇花+2。

### M6-C 屏幕时间账户

- M6.6 MUST ScreenSession{ id, startAt, endAt?, dayKey }；计时中同时只允许一个活动会话。
- M6.7 MUST 当日累计用时报 = Σ已完成会话 + 进行中会话实时时长；额度=日配置（默认40min）+结转（≤周上限默认60min）。
- M6.8 MUST 用时报超过额度：自动写 `screen_over` 扣币流水（默认−10，当日一次）并锁定创建新会话至次日；页面进入"今日已超时"态。
- M6.9 SHOULD 结转额度：家长后台可授予"额外 10 分钟券"（bankedMinutes），消费顺序：先当日额度后结转。
- M6.10 MUST 计时器在页面刷新后可恢复（以 startAt 重算，不依赖 setInterval 持久性）；浏览器关闭期间时长照 startAt/endAt 差计。

### M6-D 习惯链（21 天）

- M6.11 MUST Habit{ id, name, icon, cycleDays(默认21), milestoneRewards{7:+10,14:+20,21:+50} }；每日一次勾选成链。
- M6.12 MUST 断链：consecutive 归零但历史 milestone 徽章保留、已发奖励不回收；新一轮链重新计数。
- M6.13 MUST 里程碑发放=habit_milestone 流水，按 (habitId, milestoneIndex, chainId) 去重发放。

## M7 后台配置与家长门（views/Admin）

**职责**：配置唯一写入口；PIN 门；危险区。

- M7.1 MUST 首次运行无 PIN 时，进入后台强制设置 4 位 PIN（可跳过→使用默认 8888 并提示修改）。
- M7.2 MUST PIN 校验通过才渲染配置页；错误 5 次锁定 60s（计时用内存+lastLockUntil 持久化）。
- M7.3 MUST 可配对象：TaskItem、ShopItem、Habit、作息窗口、屏幕额度/罚则、等级阈值、textbookCoinValue、用户档案、题库导入。全部即时生效。题库导入提供 leafId 时校验存在性（自定义叶不存在返回 404，v2.1），缺省则自动建叶；`options` 兼容字符串数组（自动编 A–D 字母，`answer` 为选项文本时自动映射到对应字母）与 `{id,text}` 对象两种写法（v2.1）。
- M7.4 MUST 危险区三项：重置某档案流水、删除档案、清空全部数据——各需输入档案名确认词（如档案名）+二次确认。
- M7.5 SHOULD 配置页对孩子入口不可见（导航仅"后台配置"一项，点击即要 PIN，无"家长"字样提示）。
- M7.6 MUST 家长数据修正（v2.2，FR-26）：后台"每日计划"页提供流水列表（近 50 条）与逐条 [✏️修正]；修正=单事务内 `LedgerService.appendTx` 两步——对原流水生成 REVERSE 冲正（原流水置 revoked）+ 补录一条 `MANUAL(newAmount, reason=修正:<原因>)`，**原流水永不改写**，账本不可变性与 M9.1 唯一入口不破。可修正类型：除 REVERSE/REDEEM/REDEEM_REFUND 及已 revoked 外的全部（兑换类请走商店"撤销退款"）；`newAmount` 非 0、|newAmount|≤1000、原因必填（≥2 字）；被 PlanCheck 引用的 task 流水修正后置该勾选 `revokedTxId` 引用冲正流水，卡面保持"已勾但改数"语义由修正列表解释，不回退勾选状态。
- M7.7 MUST 后台任务表单增强（v2.2）：图标字段提供内置表情选择器（≥16 个学习/生活类图标点选即填，允许手输其他）；年级范围改为 1–6 复选框+“全部”开关，提交序列化为 `all` 或 `1,2` 形式（后端存储格式不变）。

## M8 档案与数据迁移（stores/profiles, core/backup）

**职责**：档案 CRUD、年级学期指针、导出导入、版本迁移。

- M8.1 MUST 新建档案字段：姓名(1–8字)、头像(内置8个)、年级(1–6)、学期(上/下)；数据隔离以 profileId 为唯一分区键。
- M8.2 MUST 切换档案=写 session 指针+全 store 重新水合，<500ms 完成界面刷新。
- M8.3 MUST 导出文件 = `{schemaVersion:"1.0", exportedAt, appVersion, checksum, payload:{config, profiles, ledgers, plans, textbookChecks, treesCustom, attempts, life, stats}}`，Pretty JSON、UTF-8、文件名含日期。
- M8.4 MUST checksum = 对规范化 payload（键排序、去空白）做 SHA-256；导入先校验。
- M8.5 MUST 导入流程：解析→schema 校验(zod)→checksum 比对→摘要预览（档案数/流水数/日期/与当前数据差异）→确认"将覆盖当前数据"→迁移函数链→整库替换→重新水合。任一环节失败中止且当前数据不变。
- M8.6 MUST schemaVersion > 当前应用支持版本 → 拒绝并提示升级应用；< 当前 → 逐版本 migrate 链升级。
- M8.7 SHOULD 导入前自动把当前数据下载为 `pre-import-backup-*.json`（可取消）。
- M8.8 MUST 删除档案：确认词输入 + 连带物理删除其分区数据（唯一物理删除场景）。

## M10 统计报表（v2.2 新增，FR-25；services/stats 只读聚合）

**职责**：为 P1 学习台提供周/月报表与常显进度，纯读侧聚合，不产生任何流水。

- M10.1 MUST 口径：period=week 取近 7 个自然日（含今天），month 取近 30 个自然日；被冲正(revoked)的流水及其冲正流水成对不计入收支分类合计（净额仍等于余额推导，M1 不破坏）。
- M10.2 MUST 输出块：①金币——收入/支出/净额、按来源分类（签到/学习任务/教材/生活/里程碑/惩罚/兑换/手动）；②学习——计划完成率（done/应做，同 plans/weekly 口径）、教材四进度（语/数/奥/英，奥数仅在数有奥数叶子时输出）；③自测——期内答题轮数、平均正确率、掌握度六档叶数分布（当前快照）；④生活——作息按时次数、屏幕使用分钟、习惯完成次数。
- M10.3 SHOULD 学习台 hero 下新增"📊 数据统计"卡：周/月切换按钮组+四进度条+分类收支迷你条+自测与生活摘要；数据一次请求 `/api/stats/report` 渲染，请求失败降级为"报表暂不可用"。
- M10.4 MUST 报表接口对孩子端只读、无需 PIN（不含他档数据，profileId 取 session）。

## M9 跨模块不变量（Invariants）

任何模块实现不得违反：

1. 金币唯一入口 = `LedgerService.appendTx`；其他 service 禁止直接写流水。唯一豁免（v2.1）：`BackupService` 导入时的整库替换（M8.5 语义即全量覆盖）与 `ProfileService` 删除档案时按 M8.8 连带物理清除该档案流水——两者都不是"新增激励写入路径"，不破坏账本不变量。
2. 每日一次去重键统一由 `rules/dedup.ts` 提供，禁止各模块自造去重逻辑。
3. 所有日期判定使用 `time/daykey.ts` 本地日键，禁止散落的 `new Date().toDateString()`。
4. 掌握度与进度永远由记录推导，不持久化派生值（缓存除外，缓存必须可失效）。
5. 孩子端可触发的动作集合 = {勾选计划、教材打卡、自测答题、兑换、生活打卡、屏幕计时开始/停止、切换档案}；其余全在家长门后。

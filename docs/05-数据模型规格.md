# 05 · 数据模型规格（Design）

> SSD 阶段二产出 ｜ 版本 **v2.0（MySQL + JPA + REST DTO）** ｜ 数据契约与 docs/03 微规格、docs/10 种子契约一一对应

## 1. 通用约定

- 存储引擎 InnoDB，字符集 `utf8mb4`；库名 `studyworkplace`（JDBC URL 带 `createDatabaseIfNotExist=true`）。
- 主键：`id VARCHAR(40)`（内置数据用可读 ID，见 docs/10 §2；运行时对象用 `前缀+UUID`）。
- 时间：业务日期 `day_key CHAR(10)`（服务器本地日）；时间戳 `DATETIME(3)`。
- 金币：`INT`，正收负支；枚举用 `VARCHAR` 存语义值（可读性优先）。

## 2. 档案与会话

```sql
CREATE TABLE profiles (
  id VARCHAR(40) PRIMARY KEY,
  name VARCHAR(24) NOT NULL,
  avatar VARCHAR(24) NOT NULL,
  grade TINYINT NOT NULL,               -- 1..6
  term VARCHAR(2) NOT NULL,            -- '上' | '下'
  created_at DATETIME(3) NOT NULL
);
```
当前档案=服务端会话（内存 session map，键浏览器 cookie `swp_sid`）；不落库（家庭场景够用，导出文件包含指针）。

## 3. 配置（AdminConfig 单例 + 子表）

```sql
CREATE TABLE settings (                        -- 单例行 code='singleton'
  code VARCHAR(20) PRIMARY KEY,
  pin_hash VARCHAR(120),                       -- PBKDF2WithHmacSHA256:iterations:salt:hash
  level_thresholds JSON,                       -- [0,200,600,1500,3000]
  level_names JSON,
  checkin_amount INT DEFAULT 20,
  textbook_coin_value INT DEFAULT 5,
  life_settings JSON                           -- 作息/屏幕额度/罚则（docs/03 M6）
);
CREATE TABLE task_items (
  id VARCHAR(40) PRIMARY KEY, name VARCHAR(60), icon VARCHAR(24),
  amount INT, category VARCHAR(8),             -- study|life
  grade_scope VARCHAR(32),                     -- 'all' 或 '1,3,4'
  term VARCHAR(4),                             -- 'all'|'上'|'下'
  enabled TINYINT(1), sort INT
);
CREATE TABLE shop_items (
  id VARCHAR(40) PRIMARY KEY, name VARCHAR(60), icon VARCHAR(24),
  price INT, enabled TINYINT(1), stock VARCHAR(12)   -- 'unlimited' | '5'
);
CREATE TABLE habits (
  id VARCHAR(40) PRIMARY KEY, name VARCHAR(60), icon VARCHAR(24),
  cycle_days INT DEFAULT 21, milestone_rewards JSON, enabled TINYINT(1)
);
```
默认配置（同 v1.x：6 学习项、5 家务项、6 商品）在首次启动由 `config seed` 逻辑写入。

## 4. 账本（M1）

```sql
CREATE TABLE coin_txs (
  id VARCHAR(40) PRIMARY KEY,
  profile_id VARCHAR(40) NOT NULL,
  type VARCHAR(20) NOT NULL,       -- 9 种，见 docs/03 M1 表
  amount INT NOT NULL,
  day_key CHAR(10) NOT NULL,
  created_at DATETIME(3) NOT NULL,
  ref JSON,                        -- {taskItemId|treeNodeId|shopItemId|refTxId|sessionId|habitId|milestoneIndex|chainId|redemptionId|reason}
  revoked TINYINT(1) NOT NULL DEFAULT 0,  -- 被 reverse 冲正后置 1（v2.1：释放同日重新勾选的键位）
  KEY idx_tx_profile_day (profile_id, day_key),
  -- M1.2 每日一次兜底：对可去重来源建生成列唯一索引；revoked 行生成 NULL 不参与唯一性
  dedup_key VARCHAR(190) AS (IF(revoked = 1 OR type IN ('reverse','redeem','redeem_refund','manual'),
                                 NULL, CONCAT_WS('|', profile_id, type, ref->>'$.srcId', day_key))) STORED,
  UNIQUE KEY uq_dedup (dedup_key)
);
CREATE TABLE redemptions (
  id VARCHAR(40) PRIMARY KEY,
  profile_id VARCHAR(40), item_name VARCHAR(60), price INT, icon VARCHAR(24),  -- 快照(M3边界)
  status VARCHAR(12),                -- pending|redeemed|cancelled
  created_at DATETIME(3), redeemed_at DATETIME(3),
  tx_id VARCHAR(40) NOT NULL
);
```
余额/累计/统计**永不落表**，由查询推导（M1.1）；`LedgerRule` 复算供导出校验。

## 6. 知识体系（M5）

内置结构走 `/seed/*.json` 静态通道（docs/02 ADR-13，不落库）；库中仅自定义/导入内容：

```sql
CREATE TABLE tree_nodes (
  id VARCHAR(40) PRIMARY KEY,        -- cust-* / imp-*
  subject VARCHAR(8), grade TINYINT, term VARCHAR(2),
  parent_ref VARCHAR(40),            -- seed 节点 id 或本表 id
  kind VARCHAR(8), title VARCHAR(80), sort INT, branch VARCHAR(8),
  origin VARCHAR(9)                  -- custom|imported
);
CREATE TABLE quizzes (
  id VARCHAR(40) PRIMARY KEY,
  leaf_id VARCHAR(40) NOT NULL,
  subject VARCHAR(8),
  type VARCHAR(8),                   -- single|blank
  stem VARCHAR(500), options JSON, answer VARCHAR(120), answer_accepts JSON,
  explanation VARCHAR(800), origin VARCHAR(9),
  KEY idx_quiz_leaf (leaf_id)
);
CREATE TABLE attempt_rounds (
  id VARCHAR(40) PRIMARY KEY,
  profile_id VARCHAR(40), leaf_id VARCHAR(40),
  quiz_set_hash CHAR(64),            -- SHA-256 hex（domain QuizSetHash）
  answers JSON,                      -- [{quizId,given,correct,at}]
  rate DECIMAL(4,3), mastery VARCHAR(12),
  finished_at DATETIME(3),
  KEY idx_attempt (profile_id, leaf_id, finished_at)
);
```
有效轮次查询=hash 与当前题目集一致的最近一轮（M5.6）；`GET /…/quiz` 响应必须剔除 `answer/answerAccepts` 字段（v2.0 安全条款）。

## 7. 生活（M6）

```sql
CREATE TABLE sleep_logs (

```

## 8. 导出/导入文件格式（M8，服务端生成）

```jsonc
{
  "schemaVersion": "2.0", "appVersion": "1.0.0",
  "exportedAt": "2026-10-25T12:00:00+08:00",
  "checksum": "sha256:<hex>",           // 规范化 payload（键深排序）后服务器计算
  "payload": {
    "settings": {...}, "taskItems": [...], "shopItems": [...], "habits": [...],
    "profiles": [...], "coinTxs": [...], "redemptions": [...],
    "planChecks": [...], "textbookChecks": [...],
    "customNodes": [...], "customQuizzes": [...], "attempts": [...],
    "life": { "sleepLogs":[...], "screenSessions":[...], "screenBanks":[...], "habitLogs":[...], "habitChains":[...] }
  }
}
```
导入两步（ADR-14）：`POST /api/backup/import`（带文件体）→ 服务端 `BackupFormat.validate`：schema 遍历校验→checksum→摘要预览（档案数/流水数/日期/与当前差异）+ 返回 `confirmId`（缓存 10 分钟）→ `POST /api/backup/import/confirm {confirmId}` → **单事务**：备份当前库至 `pre_import_snapshots` 表 → 清空业务表 → 插入新数据 → 重新计算 seed 合并。任一异常整体回滚。`schemaVersion` 迁移链在 `BackupFormat` 中实现（1.0→2.0 兼容读取 v1.1 本地导出的家庭老备份）。

## 9. REST DTO 命名

请求/响应 DTO 用驼峰（`profileId`,`dayKey`,`txId`…），与上列蛇形列名由 JPA/`@JsonProperty` 映射；枚举值两端一致用文档语义值（`'daily_checkin'` 等）。分页本期不需要（家庭数据量 <5 万行）。

## 10. 审批与扣分面板（v2.3 新增，M11/M12）

```sql
CREATE TABLE pending_actions (
  id VARCHAR(40) PRIMARY KEY,
  profile_id VARCHAR(40), kind VARCHAR(16), ref_id VARCHAR(64),
  amount INT, reason VARCHAR(120), day_key CHAR(10),
  status VARCHAR(10),            -- pending/approved/rejected/withdrawn
  created_at DATETIME(3), decided_at DATETIME(3), tx_id VARCHAR(40),
  evidence_ids VARCHAR(200),     -- v2.4：佐证照片 id 逗号分隔（≤3）
  active_day CHAR(10) AS (IF(status='pending', day_key, NULL)) STORED,
  UNIQUE KEY uq_pending (profile_id, kind, ref_id, active_day)  -- "申请即占位"去重：仅 pending 行参与唯一约束（M11.4），驳回/撤回后 active_day 自动置 NULL 释放占位，同日可再申请
);
CREATE TABLE penalty_presets (
  id VARCHAR(40) PRIMARY KEY, name VARCHAR(24), icon VARCHAR(8),
  amount INT,                    -- 存储正数，落账取负
  enabled TINYINT, sort INT
);
```

- 待审核状态**不侵入既有表**：孩子端/教材/生活的 pending 态一律由 `pending_actions` 联查推导（源表只在审批通过时写入最终 done 行），`ddl-auto=validate` 下现网库零 ALTER 迁移。
- `screen_sessions`/习惯链不变（豁免与里程碑见 M11.5/M6.13）。
- 导出 payload 增补 `pendingActions`、`penaltyPresets` 两个数组；`schemaVersion` 升到 `"3.0"`。**2.0→3.0 兼容策略（实现修订）**：迁移不改写 payload 内容（保 checksum 对称），导入侧对缺失新段按空集合、`approvalConfig` 缺省视为"开启审批"处理——家庭老备份可直接升读。
- 默认 penalty_presets 四条（M12.1）由 `DefaultConfigInitializer` 首启装载，删除后不复活（用户意志优先）。

## 11. 照片佐证与移动端（v2.4 新增，M13/FR-32）

```sql
ALTER TABLE pending_actions ADD COLUMN evidence_ids VARCHAR(200);  -- 逗号分隔 photo_evidences.id，≤3 张
CREATE TABLE photo_evidences (
  id VARCHAR(40) PRIMARY KEY,
  profile_id VARCHAR(40), kind VARCHAR(24),      -- task/textbook/manual/penalty/checkin…（佐证场景）
  file_path VARCHAR(200),                        -- data/evidence/<profileId>/<id>.jpg（服务端加水印后成品）
  orig_name VARCHAR(120),                        -- 原始文件名（仅展示）
  note VARCHAR(120),                             -- 提交时备注（同时印入水印）
  taken_at DATETIME(3),                          -- 上传/拍摄落库时刻（水印时间源，服务器本地时区）
  created_at DATETIME(3)
);
```

- **v2.4 增列**：`pending_actions.evidence_ids`（新库由 schema.sql 直建；v2.3 存量库部署时需一次性 `ALTER TABLE pending_actions ADD COLUMN evidence_ids VARCHAR(200)`——`ddl-auto=validate` 会报缺列，见 docs/06 T12.2）。
- 照片文件存 `data/evidence/`，不进数据库、不进导出 payload（与电子书 PDF 同策略）；档案重置/删除连带物理删除其目录。
- 导出 payload `photoEvidences` 数组（元数据行）；`schemaVersion` → `"3.1"`，缺 `photoEvidences`/`evidence_ids` 的 2.0/3.0 备份按空值容忍导入，checksum 不因缺省段改写而失配。
- 水印规则（M13.3）：右下 4 行半透明黑底白字——`YYYY-MM-DD HH:mm:ss / 事项名 / 备注（截 20 字）/ studyworkplace`；由服务端 Java2D 落档前烧录，前端不做二次处理。

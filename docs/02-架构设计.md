# 02 · 架构设计（Design）

> SSD 阶段二产出 ｜ 版本 **v2.0（Spring Boot + MySQL）**（沿革：v1.0 Vue+Vite → v1.1 原生ESM零构建 → v2.0 服务端架构；用户两次调整技术栈）｜ 前置文档：[01-需求分析](./01-需求分析.md)

## 1. 技术选型

### 1.1 决策

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **Spring Boot 3.2.x（Java 17 target，本机 JDK 18 + Maven 3.9 实测可用）** | 用户指定；嵌入式 Tomcat 单进程即可"API + 静态页"一体伺服 |
| 数据库 | **MySQL 8（本机 3306 已在运行）** | 用户指定；`createDatabaseIfNotExist=true` 自动建库 `studyworkplace` |
| ORM | Spring Data JPA（Hibernate）| 聚合边界与实体映射直观；ddl-auto=validate + schema.sql 管住结构 |
| 前端 | **原生 HTML/CSS/JS（ES Modules），置于 `src/main/resources/static`** | 延续用户"不使用 Node"约束：零 npm、零构建；由 Boot 直接伺服 |
| 测试 | JUnit 5 + Maven Surefire；domain 纯逻辑单测 + `@SpringBootTest`/MockMvc 集成 | 无 Node 测试链 |
| 运行 | `mvn spring-boot:run` 或 `java -jar target/studyworkplace-1.0.0.jar` → `http://localhost:8080` | 家庭局域网内平板亦可访问 |

### 1.2 架构升级带来的语义变化（重要）

- **数据所有权**：从"浏览器本地"上移到"家中服务器 MySQL"——数据不再绑定某台电脑某浏览器，孩子换设备用同一地址访问即可，服务器本身仍在自己家里（隐私语义不变）。导出/导入功能保留，定位改为**跨机迁移与备份**（不再救"换浏览器丢数据"）。
- **规则唯一实现**：金币/掌握度/打卡等业务规则收敛到后端 `domain` 层，杜绝多设备多浏览器下前端规则漂移；前端只做展示与交互。
- **家长门**：PIN 校验移到服务端（`POST /api/admin/unlock`，内存 token TTL 30 分钟），比"孩子端藏入口"真正多一道防线。
- **并发**：多设备同时打卡成为可能 → 写操作在服务端事务内做"每日一次"去重与余额校验，取代前端防抖。

## 2. 整体架构

```
浏览器（孩子/家长）
  静态 SPA（原生 ESM：views/components/stores-lite）
      │ fetch JSON（同源 /api/**；admin 接口带 X-Admin-Token）
┌─────▼─────────────────────────────────────────────────────────┐
│                Spring Boot 单应用（嵌入式 Tomcat :8080）         │
│  web 层    Controller（DTO 校验、鉴权 filter、静态资源伺服）        │
│  service 层 用例编排（事务边界 @Transactional 在这一层）            │
│  domain 层   纯 Java 领域逻辑（无 Spring/JPA 依赖，POJO+单测）：    │
│             LedgerRule StreakRule LevelRule GraderEngine         │
│             MasteryEngine ProgressCalc ScreenQuota BackupFormat  │
│  repo 层    Spring Data JPA Repository（唯一 MySQL 触点）          │
└─────┬──────────────────────────────────────────────────────────┘
      │ JDBC (Connector/J)
   MySQL 8 · studyworkplace（profiles/txs/plans/attempts/life… 见 docs/05）

静态内容通道：/seed/*.json（教材目录与内置知识树，打包进 jar、只读、可整体替换）
自定义内容：tree_nodes/quizzes 表（origin=custom|imported），与 /seed 在前端合并呈现
```

**分层依赖铁律**：web → service → domain / repo；domain 不 import Spring/JPA（以 ArchUnit 或 grep 门禁 `import org.springframework` on domain/ 保证）。

## 3. 领域模型

聚合划分与 v1.x 完全一致（Profile / Ledger / DailyPlan / KnowledgeSpace / LifeState 五聚合 + AdminConfig 单例；知识树结构共享、答题按档案私有）。落地为 JPA 实体映射见 docs/05 §2–§7；领域规则对象与微规格 M1–M9 的映射：

| 微规格 | domain 类 | service 类 |
|---|---|---|
| M1 账本 | `LedgerRule`（余额/累计/聚合/冲正校验）、`LevelRule`、`StreakRule` | `LedgerService`（@Transactional appendTx 唯一入口） |
| M2 计划 | `DedupKey` | `PlanService.checkTask`（PlanCheck+CoinTx 同事务） |
| M3 商店 | — | `ShopService`（兑换状态机+余额事务内重校验） |
| M4 教材 | `ProgressCalc` | `TextbookService` |
| M5 知识 | `GraderEngine`、`MasteryEngine`、`QuizSetHash` | `KnowledgeService` |
| M6 生活 | `ScreenQuota`、作息窗口判定 | `LifeService` |
| M7 后台 | `PinHash`（PBKDF2） | `AdminService` + `AdminTokenStore` |
| M8 迁移 | `BackupFormat`（结构校验+版本迁移） | `BackupService`（导出组装/导入替换，整库单事务） |

## 5. 关键机制

- **金币结算事务**：service 内 `dedup 校验 → PlanCheck upsert → domain 生成 CoinTx → repo 落库` 单事务；取消勾选生成 `reverse` 引用流水，同 docs/03 M2.2/2.3。
- **审批门（v2.3，M11）**：人类触发的加减分动作先落 `pending_actions`（不写流水）；家长 approve 的同一事务里才 `appendTx` 并回写来源状态（PlanCheck/TextbookCheck/HabitLog 等 pending→done + txId）。余额=Σ流水的不变量天然成立——待审核金额不在账本内；驳回只回滚来源状态。去重键（dayKey、首精通、里程碑）由 pending_actions 唯一索引在"申请即占位"层保证，替代原"流水落库层"去重（屏幕超时/商店兑换两个豁免路径仍走原即时逻辑）。
- **掌握度**：`QuizSetHash = SHA-256(题目id+题干+答案 摘要)` 由后端在 attempt 提交时计算落库；查询有效轮次=hash 匹配的最近一轮（M5.6 不变）。自测永不回传答案字段给答题接口（防偷看，v2.0 新增）。
- **屏幕计时**：startAt/endAt 存库、时长由服务器时钟对 `screen_sessions` 推导；页面刷新/换设备恢复进行中会话（M6.10 语义在服务器端更强）。超时判定与罚扣流水在 stop tick 的事务里完成。
- **导出/导入**：导出=服务器组装 payload+SHA-256；导入两步（validate 预览 confirmId → 确认执行），整库替换在单事务内，失败自动回滚原数据。
- **种子内容**：`/seed/*.json`（docs/10 契约）随 jar 发布；后台"重新装载 seed"接口支持家长替换文件后一键刷新内置表（origin=builtin 行级替换）。
- **局域网 H5 访问（v2.4，FR-31）**：`server.address: 0.0.0.0`（application.yml 可回退 127.0.0.1）；`/api/bootstrap` 附 `lanHint`（服务端枚举本机非回环 IPv4，供壳层展示"手机访问地址"提示）；前端全站响应式（≥3 断点：760/1024 现有基础上增 480 窄屏），相机/相册经 `<input type=file accept="image/*" capture>` 调用系统能力，无 WebView/原生壳。
- **照片水印管线（v2.4，M13）**：multipart 上传 → ImageIO 读入（限 JPEG/PNG/WebP）→ 长边降采样 ≤1600 → Java2D 右下烧录 4 行水印 → JPEG q0.85 落 `data/evidence/<profileId>/`。全链路无外网依赖。

## 7. ADR 摘要（v2.0 增补）

| # | 决策 | 理由 |
|---|---|---|
| ADR-11 | 后端 Spring Boot + MySQL 为唯一事实来源 | 用户指定；多设备一致、规则收敛、家长门真鉴权 |
| ADR-12 | 前端仍原生 ESM 置于 Boot static | 用户约束"不用 Node"延续；单 jar 部署最简 |
| ADR-13 | 内置教材/知识树走 `/seed` 静态 JSON，自定义内容入库 | builtin 可随版本整体替换、不污染用户数据（契约 docs/10 不变，三科内容资产跨架构复用） |
| ADR-14 | 导入两步式（预览→确认），服务端单事务替换 | 家庭数据误覆盖不可挽回，比 v1.1 更强保护 |
| ADR-8..10 | 随 v1.1 废弃标记 | 历史保留于版本沿革说明 |

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| MySQL 密码不符（占位 root/root） | 启动即用 JDBC 实测，失败则向用户要准确凭据后再跑，不猜不改库 |
| JDK18 与 Boot3.2 个别字节码告警 | release=17 编译目标；实测日志无 error 为准 |
| 局域网暴露面 | README 明示仅建议家庭内网；admin 接口必须 token；监听地址默认 localhost、开放局域网需用户显式改配置 |
| 多端并发打卡竞态 | 服务端事务内 dedup 唯一约束（(profile,item,day) 唯一索引），冲突返回友好提示 |

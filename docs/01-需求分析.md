# 01 · 需求分析（Specification）

> SSD 阶段一产出 ｜ 回答"做什么、为什么、做到什么程度算好" ｜ 版本 v1.0

## 1. 问题陈述

小学阶段（6–12 岁）家庭的日常督促存在三个结构性痛点：

| 痛点 | 现状 | 期望 |
|---|---|---|
| 打卡靠吼 | 每日任务口头布置，执行与否全凭家长记忆和催促 | 任务可视化、到点自查、完成状态留痕 |
| 进度靠记 | "语文学到哪儿了"没有量化口径 | 每一科、每一个知识点进度可百分比呈现 |
| 错题靠猜 | 孩子哪里不会，家长只能靠考试结果倒推 | 按知识点自动分级（精通→未掌握），红点即攻关清单 |

附带动机：市面 App 广告多、强制注册、不可定制、要会员，且数据在厂商手里。家长需要一个**数据归自己、规则自己定、孩子天天愿意打开**的工具。

## 2. 干系人与用户画像

| 角色 | 说明 | 关键诉求 |
|---|---|---|
| 家长（管理员） | 唯一拥有后台配置权限的角色，负责"定价" | 规则可定制、进度可查、数据可迁移、不做内容供应商 |
| 孩子（使用者） | 1–6 年级小学生，可有多个（如二孩家庭） | 界面直观有童趣、今天做什么一眼明了、赚金币有成就感 |
| 二孩家庭 | 家长为 broker，两个孩子独立使用 | 档案完全隔离、互不攀比（各自账本） |

## 3. 用户故事与验收标准（按模块分组）

### S1 档案与切换

- **S1.1** 作为家长，我要在后台添加多个孩子档案（姓名、头像、年级、学期），以便二孩各用各的。
  - 验收：档案数 ≤ 8；每个档案的金币、计划、进度、答题记录完全隔离；删除档案需二次确认且明确提示数据不可恢复。
- **S1.2** 作为孩子，我要在顶部一键切换档案和年级/学期，目录与任务自动跟着变。
  - 验收：切换后 500ms 内全界面刷新；未保存操作不丢失。

### S2 每日计划打卡（学习侧）

- **S2.1** 作为家长，我要配置"赚金币任务"（如阅读 30 分钟 +5、口算 +5、户外运动 20 分钟 +5、练字 10 分钟 +5）和"扣金币项"（如未按时作业 −10、超时电子设备 −10）。
  - 验收：每项可改名称/金额/适用年级，可新增可停用；默认预置原文同款 6 项。
- **S2.2** 作为孩子，我在"今日计划"清单逐项勾选，勾选即时结算金币并给出反馈动效。
  - 验收：勾选→金币余额实时更新并有 +N/−N 飘字；误勾可取消并自动冲正（记录反向流水）。
- **S2.3** 作为家长，我每天额外提供一次"每日签到 +20"按钮。
  - 验收：每档案每日仅一次（按本地日期 0 点重置），重复点击提示"今天已经签过啦"。
- **S2.4** 连续打卡：作为孩子，我坚持打卡能看到连续天数，断了归零。
  - 验收：当日任一任务或签到完成即算"打卡日"；连续天数在顶栏展示；断签次日归零并有温和提示。

### S3 金币账本与激励

- **S3.1** 系统以不可变流水记账：剩余金币 = Σ流水，累计金币 = Σ正数流水。
  - 验收：任意时刻余额可由流水复算一致；流水可按日/月/年聚合为柱状图。
- **S3.2** 等级由累计金币自动折算五级：小嫩芽→绿幼苗→向阳花→知识树→小学霸。
  - 验收：阈值默认 0/200/600/1500/3000（后台可改）；升级有一次性庆祝提示。
- **S3.3** 兑换商店：家长明码标价（看动画片 60、游戏 30 分钟 120、买书 200、周末游玩 300、点晚餐 80、晚睡 10 分钟 100，均可改）。孩子点击兑换即扣币并生成"待兑现"记录。
  - 验收：**工具只做记账，不做兑现**——兑换生成记录、金币即时扣除；家长在后台确认"已兑现"后记录归档；余额不足时兑换按钮禁用并显示差额。
- **S3.4** 防通胀边界：单项任务每日仅可计一次；扣币项由家长发起（孩子端只见结果）。

### S4 教材目录打卡

- **S4.1** 语文/数学/英语按人教版教材目录组织为可勾选条目，切年级/学期自动变化。
  - 语文按单元/识字/汉语拼音/阅读分组；数学按"校内·第 n 单元"分组并平行挂"奥数"模块；英语按 Unit 分组，Unit 下分话题词汇/核心句型/语音/交际与文化。
  - 验收：覆盖 1–6 年级上下册目录结构；每个条目勾选即打卡 +N 金币（金额后台可配）。
- **S4.2** 每个科目实时显示完成百分比（已勾条目/总条目），显示在页面右上角。
- **S4.3** 进度允许回退（误勾取消），百分比与金币同步冲正。

### S5 知识体系与自测

- **S5.0（v2.1 范围调整，v2.2 澄清）** 知识体系与自测**覆盖 1–6 年级**语文、数学、英语三科；其中 **4–6 年级为"校内知识"重点学段**（知识体系成型、可分级诊断，内容优先打磨与校对），1–3 年级保留基础版内容（识字拼音/数与运算/英语启蒙），低年级以教材目录打卡与习惯养成为主。
- **S5.1** 知识体系为四层树：年级 → 册/模块 → 单元/主题 → 知识点（叶）。数学在同年级下并列"校内"与"奥数"两个分支。
  - 验收：树可展开/收起/全展开；节点总数与末级知识点数在顶部统计正确。
- **S5.2** 每个知识点挂 1..n 道自测题（单选、填空为主），做完即时判对错并展示解析。
  - 验收：单选题即时判分；填空题去空格后精确匹配判分；答错也展示正确答案与解析；可"重做本知识点"。
- **S5.3** 掌握度按该知识点历史最佳/最近一次答题正确率自动分级：
  - ≥90% 精通（绿）｜80–90% 掌握（蓝）｜30–80% 部分掌握（黄）｜<30% 未掌握（红）｜未作答 灰。
  - 验收：口径采用"最近一次整轮正确率"（重做可覆盖），规则后台可见说明；顶部统计"精通+掌握占比"。
- **S5.4** 掌握度筛选：全部/精通/掌握/部分/未掌握/未答六档过滤树上的叶子。
  - 验收：选中"未掌握"后仅红点叶子可见，作为"明日攻关清单"；筛选状态记忆到本次会话。
- **S5.5** 学习、练习、诊断共用同一棵树：打卡条目、题目、掌握度统计指向同一知识点 ID，不维护平行清单。
- **S5.6** 内容量策略：v1.0 内置**每个年级 × 科目 × 上下册的完整单元级目录**，知识点叶子与题目内置"样例级"内容（每个单元至少 2 个知识点、每个知识点至少 2 题），并支持后台以 JSON 导入扩展题库（家长从外部题库自行整理导入）。

### S6 生活管理模块（本项目新增）

- **S6.1** 作息打卡：固定两项/日——"按时上床"与"按时起床"，家长可设置目标时间与宽限分钟，按时完成 +N 金币，超时完成 +0 并记录"迟"。
- **S6.2** 家务劳动：可配置任务池（如倒垃圾 +3、洗碗 +5、整理书桌 +4、叠被子 +2），孩子完成即打卡赚币；每项每日一次。
- **S6.3** 屏幕时间账户：家长设定每日额度（如 40 分钟）；孩子开始/停止计时，超额度自动触发扣币项并当日锁死计时器；本周剩余额度可结转（上限后台可配）。
- **S6.4** 习惯养成：21 天习惯链（如"自己收拾书包"），连续完成有里程碑徽章与奖励金币；断链不清零里程碑但连续数归零。
- **S6.5** 生活数据与学习共用同一金币账本与统计图；周报视图合并展示"学习+生活"双线完成率。

### S7 后台配置（家长侧）

- **S7.1** 单一入口「后台配置」，进入需 4 位家长 PIN（默认 8888，可改；孩子端无提示）。
- **S7.2** 可配置：用户管理、每日计划项、生活项目、兑换商店、等级阈值、各科目打卡金币值、知识体系 JSON 导入、数据危险区（清空某档案/重置流水）。
- **S7.3** 所有配置改动即时生效且写入本地存储；危险操作（清空、删除）二次确认。

### S8 数据主权与迁移

- **S8.1** 全部数据存家中服务器 MySQL（Spring Boot 单 jar 本机运行），无公网账号、无上传；任意家用设备访问同一地址得到同一数据。
- **S8.2** 「导出配置」下载一个 JSON：含**全量**——档案、后台配置、知识体系自定义内容、全部流水与打卡/答题记录、掌握度。文件名含日期，如 `studyworkplace-backup-2026-10-25.json`。
- **S8.3** 「导入配置」在新设备选择该文件后完整恢复，进度与配置一致；导入前展示摘要（档案数、流水条数、日期）并要求确认"将覆盖当前数据"。
- **S8.4** 导入格式版本化（`schemaVersion`），向后兼容迁移；损坏文件给出可读错误而非白屏。

## 5. 非功能需求（NFR）

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 离线自托管 | 服务运行于家庭内网本机（Spring Boot 单 jar），无需外网；默认仅监听 localhost，开放局域网需显式配置 |
| NFR-02 | 性能 | 首屏可交互 < 2s（中端笔记本）；树渲染 5000 节点不卡顿（虚拟滚动或懒渲染）；操作反馈 < 100ms |
| NFR-03 | 可靠性 | 任何 UI 操作崩溃不得损坏既有数据；写入采用"先备份后替换"策略 |
| NFR-04 | 隐私 | 无遥测、无第三方脚本、无公网出口；数据仅存家中 MySQL |
| NFR-05 | 可用性（儿童） | 大字号（正文≥16px）、高对比、图标+文字双编码；关键操作有即时动效反馈；不出现恐吓性负反馈文案 |
| NFR-06 | 可访问性 | 键盘可完成全部打卡操作；颜色不作为唯一信息载体（色盲友好：颜色+形状/文字） |
| NFR-07 | 可维护性 | Java 17；核心规则（金币、掌握度、打卡结算）为无框架依赖的 domain 纯逻辑并配 JUnit 单测，domain 包行覆盖 ≥ 90% |
| NFR-08 | 兼容性 | Chrome/Edge 最近两个大版本；平板（≥768px）可用 |
| NFR-09 | 数据安全 | 导入必须校验 schemaVersion 与结构；导出文件名带日期；清空类操作二次确认 |

## 6. 业务规则速查（规范化）

1. **日期口径**：一律按**服务器本地时区**自然日（家庭单机部署，全端同一口径）；"每日"重置点为 0 点。
2. **一次原则**：任务项/教材条目/习惯在同一天内仅计一次，取消勾选生成反向冲正流水。
3. **余额推导**：余额 = Σ流水金额；累计 = Σ正金额流水；不允许直接改写余额字段。
4. **掌握度口径**：一个知识点一轮 = 该知识点当前全部题目各答一次；正确率 = 答对题数/题目总数；取**最近一轮**结果分级；无答题记录 = 未答。
5. **等级门槛**：按累计金币（只增不减）判定，兑换与扣币不影响等级回落。
6. **屏幕时间**：当日计时累计 > 额度 → 自动记一笔配置的扣币流水并锁定到次日；结转额度 ≤ 配置的周上限。
7. **兑现语义**：兑换即扣币、生成 pending 记录；家长确认 → redeemed；家长可"撤销兑换"→ 生成退款流水。

## 7. "不做"清单（防范围蔓延）

不做云端同步/账号体系；不做内容采购级大题库；不做主观题自动判分；不做游戏化对战/排行榜（防攀比）；不做学习视频内嵌；扣币项不提供孩子自助发起入口。

## 8. 成功度量（v1 上线自查）

- 孩子连续 7 天自主打开完成全部今日打卡（家庭实测）
- "未掌握"红点列表每周被实际清空 ≥ 1 次
- 家长全程未口头条目超过 3 项（即所有约定都进了系统）
